# Larix CDE

Единая оболочка для интеграций с несколькими СОД.

## Структура

```text
Larix-CDE/
├─ run.bat                # запуск из исходников
├─ install_dependencies.bat
├─ build_single_exe.bat
├─ app/                   # runtime-код и ресурсы
│  ├─ launcher.py
│  ├─ core/
│  ├─ shared/
│  ├─ assets/
│  └─ plugins/            # независимые интеграции
│     ├─ larix/
│     ├─ vitrocad/
│     ├─ signal/
│     └─ projectpoint/
├─ tools/                 # сборка и проверки
├─ config/                # зависимости и pytest
├─ tests/
├─ docs/
├─ Archive/               # компактный архив исходников и шаблонов
└─ release/               # создаётся сборкой, только Larix_CDE.exe
```

Главное окно больше не содержит жёсткий список СОД. Оно автоматически читает
`app/plugins/*/plugin.py`. Чтобы добавить новый СОД, достаточно создать новую папку
плагина с `plugin.py` и entry point.

## Запуск

1. `install_dependencies.bat` — один раз установить зависимости.
2. `run.bat` — запустить Larix CDE.

Для запуска из исходников используйте `run.bat` или `py app/launcher.py` из
корня проекта.

Тема, размеры окон и навигация назад синхронизированы через `app/shared/`.

## Сборка одного EXE

Для самостоятельной сборки запустите `build_single_exe.bat` из корня проекта.
После успешной проверки готовый файл появится по адресу
`release/Larix_CDE.exe`; для работы на другом ПК нужен только этот EXE.

`Archive/` включён в GitHub в виде компактного архива исходников,
шаблонов и документации для сверки функциональности. HAR-файлы, окружения,
кэши, результаты сборки, EXE и локальные профили намеренно исключены из Git.
EXE больше 100 МБ следует прикладывать к GitHub Release, а не коммитить в
репозиторий.

## Важное

Бизнес-логика существующих четырёх приложений перенесена без переписывания:
API, Excel, создание папок, права, атрибуты и маршруты остались в соответствующих
папках `app/plugins/*`. Локальные theme-файлы сохранены как тонкие совместимые
обёртки над общим `app/shared/theme_core.py`.

`connection_profiles.json` намеренно не включён.
