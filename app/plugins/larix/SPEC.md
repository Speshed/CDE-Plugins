# Импорт типов замечаний и задач Larix

## 1. Краткое описание

В приложение Larix User Manager добавляется импорт типов замечаний и типов задач из двух независимых Excel-файлов. Для каждого типа импорт создаёт отсутствующий тип либо обновляет права существующего типа по точному названию.

## 2. Цели

- Создавать и синхронизировать типы замечаний в выбранном проекте Larix.
- Создавать и синхронизировать типы задач в выбранном проекте Larix.
- Полностью заменять права только у типов, перечисленных в импортируемом файле.
- Давать пользователю понятный предпросмотр и подтверждение до изменения данных Larix.
- Поставлять два понятных и аккуратно оформленных шаблона Excel.

## 3. Не входит в объём

- Удаление типов, отсутствующих в Excel.
- Изменение прав папок, пользователей, проектов или ролевой матрицы.
- Создание либо изменение проектных ролей и пользователей Larix.
- Импорт данных одновременно в несколько проектов.

## 4. Пользователь и сценарий

Администратор Larix авторизуется, выбирает проект в карточке типов замечаний или задач, скачивает соответствующий шаблон, заполняет его и загружает обратно. Приложение строит план изменений, показывает его, запрашивает подтверждение и выполняет импорт.

## 5. Excel-формат

Для замечаний и задач поставляются отдельные `.xlsx`-шаблоны одинаковой структуры.

### Лист `Типы`

| Название типа |
|---|
| Координационная проверка |

- Каждая непустая строка — один тип.
- Название обязательно; пробелы по краям игнорируются.
- Повторяющиеся названия в одном файле являются ошибкой предпросмотра.

### Лист `Права ролей`

| Название типа | Роль | Права |
|---|---|---|
| Координационная проверка | BIM-координатор | ПРС |

- `Роль` должна в точности совпадать с названием проектной роли Larix для выбранного проекта.
- Для одного типа и роли допускается одна строка.

### Лист `Права пользователей`

| Название типа | E-mail пользователя | Права |
|---|---|---|
| Координационная проверка | user@example.com | ПР |

- E-mail должен однозначно сопоставиться с пользователем текущего пространства Larix.
- Для одного типа и пользователя допускается одна строка.

### Коды прав

| Код | Значение |
|---|---|
| `ПР` | Просмотр |
| `С` | Создание |
| `ПРС` | Просмотр и создание |
| `-` | Нет прав |

Коды не зависят от регистра и пробелов. Значение `-` не создаёт запись права и используется для явного обозначения отсутствия права в шаблоне.

Тип из листов прав обязан присутствовать на листе `Типы`. Пустые строки игнорируются. Некорректные коды, дубликаты, неизвестные типы, роли или пользователи — ошибки предпросмотра, блокирующие импорт до исправления Excel.

## 6. Функциональные требования

### FR-1. Две карточки интерфейса

На вкладке с импортами появляются независимые карточки:

- «Типы замечаний»;
- «Типы задач».

Каждая карточка содержит выбор проекта, кнопки «Скачать шаблон» и «Загрузить файл», отображение выбранного файла, предпросмотр, сводку и кнопку импорта. Оформление и взаимодействия повторяют существующие карточки приложения.

### FR-2. Предпросмотр

После выбора проекта и Excel приложение получает текущие типы, проектные роли и пользователей Larix, разбирает файл и формирует план:

- создать тип;
- обновить права существующего типа;
- список прав «просмотр» и «создание» для ролей и пользователей;
- ошибки проверки.

Предпросмотр не изменяет данные Larix. Кнопка импорта активна только при успешном предпросмотре без ошибок.

### FR-3. Создание и поиск типа

Для замечаний используется `POST /api/remarks/types`, для задач — `POST /api/tasks/types`; тело запроса: `title`, `projectId`.

Перед созданием приложение получает список типов соответствующего вида для выбранного проекта. Тип сопоставляется по названию после удаления начальных и конечных пробелов. Если совпадение найдено, тип не создаётся; синхронизируются его права. Если совпадения нет, тип создаётся.

### FR-4. Полная синхронизация прав

Для каждого импортируемого типа приложение формирует точные списки пользователей и проектных ролей отдельно для прав просмотра и создания.

- Замечания: `PUT /api/remark-types/access` с `remarkTypeId`, `userId`, `projectRoleId`, `accessRoleId`.
- Задачи: `PUT /api/task-types/access` с `taskTypeId`, `userId`, `projectRoleId`, `accessRoleId`.
- `accessRoleId=8` — просмотр; `accessRoleId=10` — создание.

Для каждого из двух уровней доступа отправляется запрос, в том числе с пустыми массивами. Поэтому ранее назначенные, но отсутствующие в Excel права снимаются. Типы, не указанные на листе `Типы`, не меняются.

### FR-5. Подтверждение и выполнение

Перед запуском показывается подтверждение с количеством создаваемых типов, типов с обновляемыми правами и запросов прав. После подтверждения импорт выполняется последовательно в рабочем потоке, чтобы интерфейс не зависал. В журнале и итоговой сводке отражаются результаты по каждому типу.

Если сетевой запрос для типа завершился ошибкой, импорт продолжает обработку следующих типов, итог помечается как частично успешный. Автоматический повтор запросов не выполняется; пользователь может исправить проблему и повторить импорт. Уже обработанные типы повторно синхронизируются безопасно.

## 7. Техническая архитектура

- `LarixAPIClient` получает методы для списков, создания типов и полного задания прав.
- Общие модели и парсер Excel не должны дублировать логику для замечаний и задач: различаются только метаданные API (вид, URL, имя ID).
- Новый `QThread` готовит предпросмотр и отдельный `QThread` применяет сформированный план.
- UI хранит независимое состояние файлов, листов, планов и отчётов для замечаний и задач.
- Для чтения Excel используется существующий стек `pandas` / `openpyxl`; встроенные шаблоны включаются в сборку аналогично уже существующим шаблонам.

## 8. Обработка ошибок и восстановление

- Неавторизованный пользователь, невыбранный проект, отсутствующий файл и недоступные обязательные листы отображаются до предпросмотра.
- HTTP-ошибка содержит код и короткий фрагмент ответа в журнале.
- Ошибка одного типа не отменяет уже успешно применённые изменения и не препятствует оставшимся типам.
- Повторный импорт после сбоя допускается: совпавшие типы не дублируются, права снова полностью приводятся к Excel.

## 9. Совместимость

- Windows, Python, PySide6, requests, pandas и openpyxl — существующий стек проекта.
- Поддерживаются `.xlsx`, `.xls` и `.xlsm` при загрузке; скачиваемые шаблоны — `.xlsx`.
- Новые элементы сохраняют светлую и тёмную темы и существующий стиль интерфейса.

## 10. Критерии приёмки

1. Пользователь может скачать два разных шаблона: для замечаний и для задач.
2. В каждой из двух карточек можно выбрать проект, загрузить файл, увидеть предпросмотр и подтвердить импорт.
3. Отсутствующий тип создаётся в нужном API Larix, существующий не дублируется.
4. Для каждого импортируемого типа права просмотра и создания точно соответствуют Excel, включая снятие прежних прав.
5. Права ролей сопоставляются только по точному названию, пользователи — по e-mail.
6. Ошибочный Excel не даёт запустить импорт и объясняет причину.
7. Ошибка API для одного типа отражается в отчёте, остальные типы продолжают обрабатываться.
8. Исходный файл `Excel/Шаблон тип замечаний, задач.xlsx` заменён двумя понятными, визуально проверенными шаблонами в папке `Excel`.

## 11. Изменение требований: широкий формат Excel

Этот раздел заменяет раздел 5 и все противоречащие ему положения спецификации.

Два отдельных шаблона (для замечаний и задач) должны повторять широкий табличный формат и визуальный язык исходного `Excel/Шаблон тип замечаний, задач.xlsx`:

- один рабочий лист с матрицей;
- первый столбец — «Тип замечания» или «Тип задачи»;
- каждая следующая колонка матрицы — точное название проектной роли Larix **или** точное полное ФИО пользователя Larix;
- одна строка матрицы — один тип;
- значение на пересечении — `ПР`, `С`, `ПРС` или `-`;
- справа от матрицы располагается легенда и подсказки, как в исходном шаблоне; она не считается данными для импорта.

`ПР` означает просмотр, `С` — создание, `ПРС` — просмотр и создание, `-` — отсутствие права. Импорт допускает только эти четыре кода (без учёта регистра и окружающих пробелов).

Заголовок колонки сопоставляется строго: с проектной ролью по её названию либо с пользователем по его полному ФИО. Несуществующий заголовок или заголовок, который совпадает одновременно с ролью и пользователем, — блокирующая ошибка предпросмотра. В шаблоны не включаются реальные персональные данные: используются демонстрационные ФИО.

Пользователи больше не задаются по e-mail и отдельные листы `Типы`, `Права ролей`, `Права пользователей` не используются. Исходный объединённый файл остаётся нетронутым.

## 12. Изменение требований: точная структура исходного листа

Этот раздел уточняет раздел 11. Новые шаблоны должны повторять **не только общий визуальный язык, но и табличную компоновку** первого листа `Excel/Шаблон тип замечаний, задач.xlsx`:

- заголовки матрицы находятся сразу в строке 1; титульная строка, инструкция над таблицей, пустые строки перед заголовком и выпадающие списки не добавляются;
- данные типов начинаются со строки 2;
- первый столбец — тип, колонки B–M — роли и/или полные ФИО; порядок колонок и их ширины следуют исходному шаблону;
- колонка N остаётся пустой разделительной колонкой;
- легенда находится в колонках O–Q в том же виде, что в исходнике, с кодами `ПР`, `С`, `ПРС`, `-`;
- для двух новых файлов различаются только название первого столбца, демонстрационные данные и имя листа: `1. Типы замечаний` либо `1. Типы задач`.

Правило импорта остаётся прежним: получатели считываются из B–M, легенда и колонка N не участвуют в импорте.

## 13. Изменение требований: реальные справочники и отдельные вкладки

Этот раздел уточняет разделы 4, 5 и 11–12.

### Навигация приложения

Вместо общей вкладки `Типы замечаний и задач` приложение содержит две независимые вкладки:

1. `Папки и проект`;
2. `Импорт пользователей`;
3. `Типы замечаний`;
4. `Типы задач`.

Каждая вкладка типов содержит только свою карточку, свой выбор проекта, файл, предпросмотр, таблицу и импорт. Состояния остаются независимыми.

## 14. Восстановление вкладки ролевой матрицы

Вкладка `Ролевая матрица` является существующей функцией приложения и должна быть сохранена. Итоговый порядок навигации:

1. `Ролевая матрица`;
2. `Папки и проект`;
3. `Импорт пользователей`;
4. `Типы замечаний`;
5. `Типы задач`.

Все существующие элементы и сценарии ролевой матрицы остаются без изменений.

## 16. Оформление типов по образцу ролевой матрицы

Логика загрузки и импорта типов не меняется: выбор проекта и файла, строгая проверка, предпросмотр, подтверждение, создание отсутствующих типов и полная синхронизация прав остаются прежними.

Меняется только представление:

- два Excel-шаблона типов сохраняют компоновку и импортный формат `Excel/Шаблон тип замечаний, задач.xlsx`;
- все скачиваемые шаблоны приложения приводятся к единой палитре, шрифтам, заголовкам, границам и визуальной иерархии на основе синего оформления существующих матриц;
- при унификации оформления не меняются имена листов, заголовки импортных полей, порядок и назначение колонок, типы/папки, коды прав, формулы, проверки данных и прочее функциональное наполнение;
- кнопки `Скачать шаблон` на обеих вкладках выдают именно эти обновлённые встроенные файлы;
- вкладки `Типы замечаний` и `Типы задач` используют визуальную иерархию карточки ролевой матрицы: описание назначения, легенду кодов, сводку предпросмотра, кнопку `Подробнее`, таблицу плана и действия;
- кнопка `Подробнее` показывает развёрнутую информацию о плане: создаваемые/обновляемые типы, получатели прав и ошибки;
- существующие статусы, иконки и независимые состояния обеих вкладок сохраняются.

Из шаблонов типов удаляется только персональный получатель `Викторов Дмитрий`: очищаются его заголовок и демонстрационные коды прав под ним без сдвига остальных колонок и без замены выдуманной ролью. Все остальные получатели должны быть проектными ролями. Синтетические примеры `АТестов`, `Тест1` и `Тест2` в шаблоне импорта пользователей сохраняются.

## 15. Единое оформление вкладок типов

Карточки `Типы замечаний` и `Типы задач` визуально следуют существующей вкладке `Импорт пользователей`:

- кнопки скачивания, загрузки, предпросмотра, подробностей и импорта используют существующие PNG-иконки;
- после выбора Excel кнопка загрузки показывает состояние выбранного файла (текст, иконка и tooltip);
- карточка содержит строку статусов импорта: `Успешно`, `Уже добавлен`, `Ошибка`;
- сводка и состояние кнопок обновляются во время предпросмотра и импорта;
- применяются существующие object names/QSS и поведение светлой и тёмной тем, без новых графических ресурсов.

## 17. Регрессионная совместимость импорта ролевой матрицы

Эталоном существующего поведения служит `Новая папка/Plugin_platfrom-main/Larix_User_Platform.py`.

Проведённое сравнение подтверждает, что в текущей версии не изменились:

- разбор Excel и набор кодов прав;
- сопоставление проектных ролей и пользователей;
- получение дерева папок и текущих прав;
- построение предпросмотра;
- применение и повторная проверка прав;
- API-методы, адреса запросов и тела запросов;
- функциональное содержимое встроенного шаблона ролевой матрицы.

Обнаруженные отличия являются только интерфейсными: используется иконка `krug_galka.png` вместо `check mark.png`, а выбор проекта, листа и фильтра подробностей реализован через `NoWheelComboBox`. Эти отличия сохраняются.

Оформление вкладок типов и обновление скачиваемых шаблонов не должны менять импорт ролевой матрицы. Встроенный файл ролевой матрицы получает новое оформление и поэтому новый SHA-256, но его листы, функциональные диапазоны, значения и формулы сохраняются. Для одинакового файла, проекта и состояния Larix текущая версия должна строить тот же план и отправлять те же запросы, что и эталонная версия.
