# Спецификация: единая переносимая сборка Larix CDE

## 1. Краткое описание

Larix CDE — настольная Windows-оболочка на Python и PySide6, из которой
запускаются четыре инструмента для работы с СОД: Larix Platform, VitroCAD,
SIGNAL Docs и Project Point.

Текущая сборка сначала создает отдельный дистрибутив каждого инструмента, а
затем вкладывает все эти дистрибутивы в еще один PyInstaller `onefile`. Из-за
повторного включения Python, PySide6, Qt и библиотек обработки Excel итоговый
`Larix_CDE.exe` занимает около 1 ГБ.

Необходимо заменить вложенную упаковку одной общей PyInstaller-сборкой, в
которой зависимости хранятся в одном экземпляре, а каждый инструмент
запускается через внутренний режим того же `Larix_CDE.exe`.

## 2. Цели

1. Получать один переносимый файл `portable/Larix_CDE.exe` размером не более
   500 МБ.
2. Для переноса на другой компьютер пользователь должен копировать только этот
   EXE: внешние папки с изображениями, DLL, Python или другими ресурсами не
   требуются.
3. Сохранить функциональность всех четырех инструментов, включая встроенную
   CAPTCHA в SIGNAL через Qt WebEngine.
4. Исключить повторное включение одних и тех же сред выполнения и библиотек.
5. Сохранить привычный внешний вид, общую тему и существующую бизнес-логику.

## 3. Не входит в задачу

- Изменение API-интеграций, Excel-операций, правил работы с папками, правами,
  атрибутами и маршрутами.
- Переработка дизайна окон.
- Удаление Qt WebEngine или замена встроенной CAPTCHA внешним браузером.
- Создание установщика, автообновления или поддержки 32-битной Windows.
- Включение пользовательских паролей, токенов или профилей подключения в EXE.

## 4. Целевые пользователи и платформа

- Пользователи существующих интеграций Larix CDE.
- Windows 10 и Windows 11, архитектура x64.
- На целевом компьютере не должны требоваться установленный Python, PySide6
  или другие Python-пакеты.

## 5. Функциональные требования

### FR-1. Единый дистрибутив

- Результат сборки — ровно один обязательный распространяемый файл
  `portable/Larix_CDE.exe`.
- Все изображения, шаблоны и исполняемые зависимости должны находиться внутри
  EXE и извлекаться PyInstaller автоматически.
- После сборки рядом с EXE не должно быть обязательных для запуска папок
  `_internal`, `assets`, `plugins` или отдельных EXE инструментов.
- Приложение может создавать пользовательские настройки, профили и журналы во
  время работы; они не являются частью распространяемого комплекта.

### FR-2. Главное меню

- Обычный запуск `Larix_CDE.exe` открывает существующее главное меню выбора
  СОД.
- Карточки и порядок четырех СОД остаются прежними.
- При выборе карточки главное меню скрывается, а выбранный инструмент
  запускается отдельным процессом того же `Larix_CDE.exe` во внутреннем режиме.
- Внутренний параметр запуска не должен требоваться или отображаться обычному
  пользователю.

### FR-3. Навигация и завершение

- Кнопка «Все СОД» с изображением `exit.png` в левом верхнем углу каждого
  инструмента завершает процесс инструмента специальным кодом возврата.
- Получив код возврата, главное меню снова показывается и становится активным.
- Нажатие системного крестика окна инструмента закрывает инструмент и скрытый
  процесс главного меню, то есть завершает Larix CDE полностью.
- После закрытия крестиком главное меню не должно появляться повторно.
- Настройки темы и геометрии окон продолжают сохраняться существующим
  механизмом `QSettings`.

### FR-4. Инструменты

- Из общего EXE должны запускаться Larix Platform, VitroCAD, SIGNAL Docs и
  Project Point.
- Каждый инструмент должен сохранять текущие заголовок, основное окно,
  элементы управления и бизнес-функции.
- Ошибка импорта или запуска инструмента должна отображаться пользователю, а
  диагностическая информация должна сохраняться в журнале. После подтверждения
  сообщения об ошибке приложение завершается, не возвращаясь молча в меню.

### FR-5. SIGNAL и CAPTCHA

- Встроенный `QWebEngineView` остается доступным.
- OAuth/PKCE и сценарий CAPTCHA не меняются.
- В комплекте WebEngine остается только русская локаль.
- Английская и остальные локали WebEngine не включаются.
- Отладочные `.debug.pak` и debug snapshot-файлы WebEngine не включаются.
- Обязательные runtime-ресурсы WebEngine, необходимые для CAPTCHA, сохраняются.

### FR-6. Сборка

- Корневая сборка не должна предварительно собирать и вкладывать отдельные EXE
  четырех инструментов.
- Исходные модули инструментов анализируются и упаковываются одной операцией
  PyInstaller.
- `--collect-all PySide6` не используется для итоговой сборки.
- Неиспользуемые Qt-модули, QML-компоненты и ресурсы исключаются только при
  наличии подтверждения сборкой и smoke-тестами, что основные окна и
  Qt WebEngine запускаются.
- Сценарий сборки должен завершаться ошибкой, если итоговый EXE отсутствует,
  превышает 500 МБ или рядом с ним остались обязательные файлы дистрибутива.

## 6. Пользовательские сценарии

### WF-1. Запуск инструмента и возврат

1. Пользователь запускает `Larix_CDE.exe`.
2. Открывается главное меню.
3. Пользователь выбирает СОД.
4. Главное меню скрывается, открывается выбранный инструмент.
5. Пользователь нажимает кнопку «Все СОД».
6. Инструмент закрывается, главное меню появляется снова.

### WF-2. Полное завершение

1. Пользователь запускает инструмент из главного меню.
2. Пользователь нажимает системный крестик инструмента.
3. Инструмент и скрытое главное меню завершаются.
4. На экране не остается окон или фоновых процессов Larix CDE.

### WF-3. CAPTCHA SIGNAL

1. Пользователь открывает SIGNAL Docs.
2. Во время авторизации сервер требует CAPTCHA.
3. CAPTCHA открывается во встроенном Qt WebEngine.
4. Пользователь проходит CAPTCHA, после чего существующий OAuth/PKCE-сценарий
   продолжает работу.
5. Отсутствие английской локали не должно мешать загрузке страницы; интерфейс
   WebEngine использует русские ресурсы.

## 7. UI

- Дизайн главного меню и окон инструментов не перерабатывается.
- Кнопка «Все СОД» остается слева сверху и использует встроенный `exit.png`.
- Кнопка показывается только при запуске инструмента из главного меню.
- Системный крестик визуально и функционально остается стандартным элементом
  Windows, но теперь означает полное завершение приложения.

## 8. Архитектура

### 8.1. Единая точка входа

`Larix_CDE.exe` поддерживает два внутренних режима:

- без служебного аргумента — главное меню;
- со служебным идентификатором плагина — запуск одного инструмента.

Главное меню запускает `sys.executable` повторно, передавая идентификатор
инструмента. Это сохраняет изоляцию процессов и не требует четырех вложенных
EXE.

### 8.2. Протокол завершения

- Нормальное завершение event loop инструмента после системного закрытия имеет
  обычный код завершения и означает «закрыть всё».
- Кнопка «Все СОД» завершает event loop с отдельным зарезервированным кодом.
- Главное меню показывается повторно только для этого зарезервированного кода.
- Аварийный ненулевой код не трактуется как возврат в меню.

### 8.3. Ресурсы

- Общие изображения и необходимые данные включаются в PyInstaller bundle.
- Во frozen-режиме ресурсы читаются из `sys._MEIPASS` через существующий слой
  путей и переменные окружения менеджера.
- Пользовательские файлы не должны записываться в `sys._MEIPASS` как в
  постоянное хранилище.

### 8.4. PyInstaller

- Все Python-модули четырех инструментов включаются в один `Analysis`.
- Общие зависимости (`PySide6`, `requests`, `openpyxl`, `pandas`, `numpy` и
  другие реально используемые библиотеки) упаковываются один раз.
- Фильтрация WebEngine удаляет только debug-ресурсы и локали кроме `ru.pak`.
- Дополнительные исключения Qt применяются консервативно и проверяются запуском.

## 9. Интеграции и аутентификация

- Все существующие сетевые API и механизмы аутентификации сохраняются.
- Секреты и учетные данные не добавляются в репозиторий или сборку.
- Автоматическая проверка не требует реальных учетных данных.
- Живой вход и CAPTCHA требуют ручной приемочной проверки пользователем.

## 10. Ошибки и восстановление

- Ошибки сборки возвращают ненулевой код и понятное сообщение.
- Отсутствие обязательного ресурса считается ошибкой сборки или smoke-теста.
- Если инструмент аварийно завершился, главное меню отображает диагностическое
  сообщение, после чего Larix CDE полностью завершается.
- Повторный обычный запуск EXE после ошибки снова открывает главное меню.

## 11. Пограничные случаи

- Неизвестный внутренний идентификатор плагина завершается с ошибкой и не
  открывает главное меню как будто запуск успешен.
- Быстрые повторные нажатия по карточке не запускают несколько процессов.
- Возврат из одного инструмента позволяет затем открыть другой.
- Закрытие главного меню крестиком завершает приложение.
- Путь к EXE может содержать пробелы и кириллицу.
- Сборка и запуск не зависят от текущего рабочего каталога.

## 12. Ограничения и совместимость

- Windows 10/11 x64.
- Формат поставки — PyInstaller `onefile`.
- Встроенная CAPTCHA является обязательной, поэтому крупные бинарные компоненты
  Qt WebEngine сохраняются; уменьшение ниже размера обязательного WebEngine не
  является целью.
- Изменения должны учитывать существующие незакоммиченные изменения и не
  откатывать несвязанные правки пользователя.

## 13. Критерии приемки

1. `portable/Larix_CDE.exe` существует и имеет размер не более 500 МБ.
2. Для запуска на чистой Windows 10/11 x64 достаточно скопировать один EXE.
3. Главное меню запускается без внешних `assets`, `plugins`, `_internal` и
   отдельных EXE.
4. Из меню успешно открывается каждое из четырех основных окон.
5. Кнопка «Все СОД» в каждом инструменте возвращает в главное меню.
6. Системный крестик каждого инструмента завершает всё приложение и не
   возвращает в меню.
7. SIGNAL создает встроенный `QWebEngineView`, а обязательные WebEngine runtime
   ресурсы находятся внутри сборки.
8. В сборке присутствует `ru.pak`, отсутствуют остальные локали WebEngine и
   debug-ресурсы.
9. Существующие автоматические тесты Project Point проходят.
10. Проверка структуры проекта, проверка единственного файла поставки и новые
    тесты протокола запуска/возврата проходят.
11. Живая авторизация и прохождение CAPTCHA отмечены как ручная проверка и не
    объявляются автоматически протестированными без учетных данных.

## 14. Подтвержденные требования, допущения и идеи

### Подтверждено

- Windows 10/11 x64.
- Один переносимый EXE без обязательных внешних файлов.
- CAPTCHA и встроенный WebEngine сохраняются.
- Оставляется только русская локаль WebEngine.
- Размер итогового EXE — не более 500 МБ.
- Кнопка `exit.png` возвращает в меню; системный крестик закрывает всё.

### Допущения

- Создаваемые во время работы пользовательские настройки, профили и журналы не
  нарушают требование «передавать один EXE».
- При аварии инструмента пользователю сначала показывается ошибка, затем
  завершается вся оболочка.
- Производительность запуска вторична относительно корректности и размера, но
  не должна быть заметно хуже текущей вложенной сборки.

### Необязательные идеи вне текущего объема

- Подпись EXE сертификатом.
- Установщик и автообновление.
- Перенос пользовательских данных целиком в `%LOCALAPPDATA%`.

# Дополнение: аудит Archive и унификация Excel-шаблонов

## 15. Цель дополнения

Проверить, что при переходе от версий в `Archive` к текущей единой сборке не
потеряна прикладная функциональность, обеспечить скачивание актуального
Excel-шаблона во всех сценариях ручного импорта и привести шаблоны к одному
визуальному языку без изменения их структуры и смысла.

## 16. Результат предварительного аудита Archive

Сопоставлены четыре производственные пары:

- `Archive/Создание папок платформа` → `plugins/larix`;
- `Archive/Signal` → `plugins/signal`;
- `Archive/VitroCAD` → `plugins/vitrocad`;
- `Archive/ProjectPoint` → `plugins/projectpoint`.

Статический анализ файлов, классов, функций и методов не выявил удалённых
прикладных обработчиков. Найденные изменения относятся к общей оболочке,
кнопке возврата, теме, компоновке, предпросмотру таблиц и безопасному закрытию
файлов. В текущей версии также присутствуют новые entry point/plugin-модули и
общие UI-компоненты. Для подтверждения результата после изменений должны быть
повторно запущены существующие тесты и добавлены проверки шаблонов.

`Archive/Projectpoint Web` рассматривается как отдельный экспериментальный
прототип авторизации и перехвата токена, а не как предыдущая производственная
версия текущего инструмента Project Point. Перенос его отдельного окна в текущий
Project Point в это дополнение не входит. Текущие сетевые сценарии Project Point
и обязательная CAPTCHA не изменяются.

## 17. Покрытие скачиваемыми шаблонами

Кнопка скачивания должна быть доступна в каждом интерфейсном блоке, где
пользователь вручную заполняет и затем загружает Excel-файл.

### 17.1. Уже покрытые сценарии

- Larix: ролевая матрица, папочная структура, пользователи, типы замечаний,
  типы задач, маршруты согласований — 6 шаблонов.
- SIGNAL: права, папочная структура, атрибуты — 3 шаблона.
- Project Point: параметры, виды документов, типы документов, маршруты,
  объекты строительства, роли — 6 шаблонов.

### 17.2. Недостающее покрытие

В VitroCAD сейчас имеются только кнопки загрузки. Необходимо добавить
`Скачать шаблон` для трёх сценариев:

1. папочная структура;
2. матрица прав;
3. план-график.

Новые книги VitroCAD формируются внутри приложения и включаются в единый EXE;
внешние папки с шаблонами не требуются. Их минимальная структура должна быть
совместима с текущими парсерами и архивными примерами.

Импорт комментариев Larix из отчёта Revit не считается сценарием ручного
заполнения: файл создаётся специализированным процессом Revit и содержит
служебные данные. Создание пустого шаблона для него не входит в объём работ.

## 18. Единый визуальный формат Excel

За основу принимается визуальный язык действующих шаблонов SIGNAL и палитра
Larix CDE:

- основной шрифт: `Segoe UI`, 10 pt;
- заголовок книги/раздела: 14–15 pt, полужирный, белый текст на фоне
  `#2F2F2F`, если в существующей структуре есть отдельная строка заголовка;
- заголовки таблиц: 10 pt, полужирный, белый текст на фоне `#F7921E`;
- информационные строки: фон `#FFF4E8`, приглушённый текст `#666666`;
- границы таблиц: тонкие, `#D9D9D9`;
- перенос текста и вертикальное выравнивание применяются последовательно;
- размеры строк и колонок приводятся к читаемому виду без перестановки данных;
- сетка листа может быть скрыта там, где это не мешает существующему шаблону.

Существующая семантическая окраска сохраняется: обязательные поля, закрытые
права, ошибки и чередование строк не теряют своего значения.

### 18.1. Структурные ограничения

Для существующих шаблонов запрещено изменять:

- названия, порядок, видимость и количество листов;
- названия и порядок колонок;
- расположение заголовков и строк данных;
- значения примеров, формулы и типы данных;
- объединённые диапазоны;
- проверки данных, выпадающие списки и защищённые/служебные области;
- имена файлов, ожидаемые приложением, и алгоритмы импорта.

Допустимы только визуальные свойства ячеек и листов: шрифт, размер, цвет,
заливка, границы, выравнивание, перенос, ширина колонок и высота строк.

## 19. Подпись в главном меню

В нижней части главного меню, рядом с существующей подсказкой и над строкой
версии, добавить центрированную тематически оформленную рекомендацию:

> Перед каждым заполнением рекомендуем скачивать актуальные шаблоны.

Подпись должна быть читаема в светлой и тёмной теме, не перекрывать карточки и
не менять поведение навигации.

## 20. Поставка и совместимость

- Результат по-прежнему поставляется одним `portable/Larix_CDE.exe`.
- Скачиваемые шаблоны не требуют внешних файлов рядом с EXE.
- CAPTCHA, Qt WebEngine, русская локаль и существующая навигация сохраняются.
- Размер EXE после изменений остаётся не более 500 МБ.
- Несвязанные пользовательские изменения в рабочем дереве не откатываются.

## 21. Проверка и критерии приёмки дополнения

1. Для каждой из четырёх СОД составлена и сохранена карта соответствия старых
   и текущих функций; удалённых производственных обработчиков нет либо каждый
   найденный разрыв явно исправлен.
2. Во всех 18 сценариях ручного Excel-импорта доступно скачивание шаблона:
   Larix — 6, SIGNAL — 3, Project Point — 6, VitroCAD — 3.
3. Каждый скачанный файл открывается как корректный `.xlsx` и читается тем же
   парсером, для которого предназначен.
4. Структурная сигнатура 15 существующих шаблонов до и после стилизации
   совпадает по ограничениям раздела 18.1.
5. Все шаблоны используют согласованную палитру, типографику и близкие размеры
   текста; итоговые книги проходят визуальную проверку рендером.
6. В главном меню отображается рекомендация из раздела 19 в обеих темах.
7. Существующие root- и Project Point-тесты проходят; добавленные тесты
   генерации и round-trip шаблонов также проходят.
8. `build_single_exe.bat` выполняет проверку проекта, полную сборку одного EXE
   и итоговую проверку поставки. В рамках текущего цикла BAT подготавливается и
   проверяется статически, но сама пересборка EXE не запускается по решению
   пользователя.
9. Живые операции с внешними серверами, авторизация и CAPTCHA остаются ручной
   приёмочной проверкой и не объявляются протестированными автоматически.

## 22. Допущения, требующие подтверждения

- Единый стиль из раздела 18 применяется ко всем скачиваемым шаблонам, включая
  сложные многостраничные книги, но только в пределах существующей структуры.
- Отдельный экспериментальный `Archive/Projectpoint Web` не переносится.
- Рекомендация в главном меню добавляется отдельной строкой, а существующая

- Пересборка `portable/Larix_CDE.exe` и packaged smoke отложены до ручного
  запуска пользователем подготовленного `build_single_exe.bat`.
## 23. Исправление запуска плагинов в single-file сборке

- В режиме PyInstaller one-file загрузчик не должен требовать наличия исходных
  `*.py` entry point или старых отдельных `dist\\*.exe` рядом с распакованными
  дескрипторами плагинов.
- Для frozen-режима валидным entry point считается зарегистрированный внутренний
  модуль из `core.plugin_dispatcher.PLUGIN_ENTRY_POINTS`; исходный режим сохраняет
  текущую проверку существования файла.
- Ошибка «не найден ни исходный entry point, ни собранный» для четырёх штатных
  плагинов после сборки `Larix_CDE.exe` недопустима.
- Проверка должна быть покрыта автоматическим тестом без фактической пересборки
  EXE в текущем цикле. Итоговую сборку пользователь запускает самостоятельно
  через `build_single_exe.bat`.
