# План: упорядочивание структуры репозитория Larix CDE

## T-01. Перенести runtime-код в `app/`

**Требования:** FR-1, FR-2.

**Файлы:** `launcher.py`, `assets/`, `core/`, `plugins/`, `shared/`, `run.bat`.

**Работы:**

- создать `app/` и перенести туда entry point, ресурсы и runtime-модули;
- обновить корневой `run.bat`;
- исправить вычисление корня ресурсов и запуск внутренних режимов;
- не менять интерфейс и бизнес-логику плагинов.

**Приёмка:** приложение импортируется и каждый внутренний режим проходит
безопасный source smoke-тест; пути не зависят от текущей директории.

## T-02. Разнести сборочные инструменты и конфигурацию

**Требования:** FR-3, FR-4.

**Файлы:** `build_single_exe.py`, `Larix_CDE.spec`, `verify_project.py`,
`verify_single_exe.py`, `smoke_portable.py`, `requirements.txt`, `pytest.ini`,
`build_single_exe.bat`, `install_dependencies.bat`.

**Работы:**

- перенести Python-сценарии и spec в `tools/`;
- перенести зависимости и pytest-конфигурацию в `config/`;
- обновить вычисление корня проекта во всех сценариях;
- заменить пути `portable` на `release`;
- хранить лог и временную сборку вне набора корневых файлов;
- сохранить четыре этапа существующего build workflow.

**Приёмка:** BAT-файлы находят новые пути; проверка проекта проходит;
PyInstaller-команда формируется с правильными путями; полная сборка не
запускается.

## T-03. Обновить тесты, игнорирование и документацию

**Требования:** FR-4, FR-5.

**Файлы:** `tests/`, `config/pytest.ini`, `.gitignore`, `README.md`, документы.

**Работы:**

- обновить импорты тестов после переноса инструментов;
- настроить testpaths/pythonpath/norecursedirs;
- исключить `release/`, build-workdir и логи из Git;
- обновить дерево каталогов и команды в README;
- перенести текущие `SPEC.md` и `TASKS.md` в `docs/repository-layout/` после
  завершения реализации.

**Приёмка:** все тесты проходят одной документированной командой, ссылки README
работают, в `Archive` нет игнорируемых локальных артефактов.

## T-04. Финальная проверка структуры

**Требования:** все критерии приёмки SPEC.

**Работы:**

- проверить точный список корневых файлов;
- выполнить pytest и проверку структуры;
- выполнить `git diff --check`;
- проверить игнорирование `release/Larix_CDE.exe`;
- проверить отсутствие крупных или локальных файлов, случайно попавших в Git;
- не запускать полную сборку EXE.

**Приёмка:** выполнены пункты 1–10 раздела 10 `SPEC.md`; выявленные проблемы
исправлены отдельной сфокусированной задачей implementer-а и проверены повторно.
