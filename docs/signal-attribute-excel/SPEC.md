# Спецификация: импорт атрибутов SIGNAL из Excel

## 1. Краткое описание

На вкладке SIGNAL «Атрибуты» ручной ввод одного атрибута заменяется импортом
заполненного Excel-шаблона. Пользователь скачивает существующий шаблон,
заполняет его, выбирает файл, отдельно запускает предпросмотр и только после
успешной проверки создаёт отсутствующие атрибуты в выбранном проекте SGNL.

## 2. Цели

1. Убрать ручное заполнение полей атрибута и кнопку добавления в очередь.
2. Добавить понятный сценарий «шаблон → загрузка → предпросмотр → создание».
3. До сетевого изменения показать все строки файла, ошибки и существующие
   атрибуты.
4. Не допускать частичного применения файла с ошибками.
5. Сохранить текущий API создания, авторизацию, выбор проекта и таблицу
   атрибутов проекта.

## 3. Не входит в задачу

- Изменение API SIGNAL и структуры создаваемого payload.
- Обновление или удаление существующих атрибутов.
- Изменение вкладок ролевой матрицы и папочной структуры.
- Изменение `Archive`.
- Полная пересборка EXE.

## 4. Пользовательский сценарий

1. Пользователь выбирает компанию и проект и выполняет вход.
2. На вкладке «Атрибуты» скачивает `SGNL_Шаблон_Атрибуты.xlsx`.
3. Заполняет рабочий лист «Атрибуты» и сохраняет файл.
4. Нажимает «Загрузить из Excel» и выбирает `.xlsx` или `.xlsm`.
5. Программа показывает выбранное имя файла, очищает прежний предпросмотр и
   ожидает нажатия «Предпросмотр».
6. По кнопке «Предпросмотр» программа разбирает файл, загружает актуальные
   атрибуты проекта и заполняет таблицу результатов.
7. Если в файле есть ошибки, создание блокируется до исправления файла и
   повторного предпросмотра.
8. Строки с уже существующими в SGNL именами помечаются «Уже существует» и не
   создаются; корректные отсутствующие строки остаются готовыми к созданию.
9. По кнопке «Создать атрибуты» после подтверждения создаются только строки со
   статусом «Готов к созданию».

## 5. Интерфейс

### 5.1. Удаляемые элементы

- поля «Название», «Тип», «Область»;
- флажок «Обязательный атрибут»;
- поле вариантов списка;
- кнопки «Добавить в очередь» и «Удалить выбранные».

Свободное ручное редактирование предпросмотра не допускается: источником
данных остаётся Excel.

### 5.2. Новый блок

Блок оформляется по образцу существующей вкладки «Папочная структура» и
содержит:

- заголовок с `preview.png`;
- краткую инструкцию и предупреждение, что демонстрационные строки шаблона
  являются обычными строками и перед рабочим импортом их следует заменить или
  удалить;
- состояние выбранного файла;
- таблицу предпросмотра;
- кнопки «Открыть лог», «Скачать шаблон Excel», «Подробнее»,
  «Загрузить из Excel», «Предпросмотр», «Создать атрибуты».

Таблица предпросмотра показывает как минимум:

- статус;
- номер строки Excel;
- название;
- тип;
- область;
- обязательность;
- значения списка;
- комментарий или текст ошибки.

Таблица «Атрибуты текущего проекта» и кнопка «Обновить список» сохраняются.

## 6. Формат Excel

- Поддерживаются `.xlsx` и `.xlsm`.
- Используется лист `Атрибуты`.
- Заголовки рабочего листа:
  `Название`, `Тип`, `Область`, `Обязательный`, `Значения списка`.
- Пустые строки игнорируются.
- Демонстрационные строки существующего шаблона сохраняются без изменения и
  при загрузке обрабатываются как реальные данные.

### 6.1. Допустимые значения

- Тип: `Текст`, `Да/Нет` (также допускаются пробелы вокруг `/`), `Дата`,
  `Список`.
- Область: пусто или `Без области`, `Элемент / файл`, `Папка`.
- Обязательный: `Да` или `Нет`.
- Значения списка разделяются `;`, переводами строк или их сочетанием;
  пробелы по краям удаляются, повторяющиеся значения устраняются с сохранением
  порядка.

### 6.2. Ошибки файла

Ошибками, блокирующими создание всего файла, считаются:

- отсутствующий лист или обязательный заголовок;
- частично заполненная строка без названия;
- неизвестный тип, область или значение обязательности;
- тип `Список` без вариантов;
- значения списка у типа, отличного от `Список`;
- повтор названия внутри Excel без учёта регистра и окружающих пробелов;
- отсутствие хотя бы одной непустой строки.

Ошибочные строки остаются видимыми в предпросмотре со статусом «Ошибка».

## 7. Состояние и безопасность применения

- Выбор нового файла полностью сбрасывает старый предпросмотр.
- Изменение компании или проекта инвалидирует предпросмотр.
- Кнопка создания недоступна до успешного предпросмотра.
- Перед созданием проверяется, что выбранный файл не изменился после
  предпросмотра; при изменении требуется повторная проверка.
- Перед отправкой worker повторно получает список атрибутов SGNL и пропускает
  активные дубликаты, как и текущая реализация.
- При наличии ошибок Excel ни одна строка не отправляется в API.
- Если все строки уже существуют, создание не запускается и показывается
  понятное сообщение.
- Сетевые ошибки используют существующий журнал и обработчики SIGNAL.

## 8. Архитектура

- Парсер Excel реализуется отдельно от Qt-обработчиков, чтобы его можно было
  тестировать без открытия окна.
- Парсер возвращает строки предпросмотра, нормализованные drafts и полный
  список ошибок.
- Существующий `CreateAttributeTypesWorker` и формат drafts сохраняются.
- Сетевое сравнение выполняется на этапе предпросмотра, а не при простом выборе
  файла.
- Новые внешние зависимости не добавляются; используется текущий `openpyxl`.

## 9. Документация и тесты

- README SIGNAL обновляется под обязательный Excel-сценарий.
- Добавляются тесты генератора и парсера атрибутов: валидный шаблон,
  нормализация, пустой файл, неверные заголовки, неверные значения, пустой
  список и дубликаты.
- После реализации этот `SPEC.md` и `TASKS.md` переносятся в
  `docs/signal-attribute-excel/`, чтобы корень репозитория снова содержал только
  пользовательские точки входа.

## 10. Критерии приёмки

1. На вкладке атрибутов нет ручной формы и ручного добавления строк.
2. Есть кнопки загрузки Excel и отдельного предпросмотра в стиле других блоков.
3. Сгенерированный шаблон успешно разбирается без изменения структуры.
4. Демонстрационные строки шаблона сохранены.
5. Все блокирующие ошибки из раздела 6.2 видны пользователю и не позволяют
   создать ни одной строки.
6. Существующие атрибуты помечаются и пропускаются, остальные можно создать.
7. Новый файл или новый проект сбрасывает разрешение на создание.
8. Тесты проекта и проверка структуры проходят.
9. `.gitignore` не допускает кэши, логи, локальные Excel пользователя и
   результаты сборки; встроенные шаблоны проекта не исключаются.
10. PyInstaller не запускается без отдельного запроса пользователя.
