# План: импорт атрибутов SIGNAL из Excel

## T-01. Реализовать и протестировать парсер шаблона атрибутов

**Требования:** разделы 6, 7 и 8 SPEC.

**Файлы:** `app/plugins/signal/SIGNAL.py`, новый тест
`tests/test_signal_attribute_excel.py`.

**Работы:**

- реализовать независимый от UI разбор листа `Атрибуты`;
- нормализовать тип, область, обязательность и значения списка;
- возвращать номер исходной строки, draft, статус и ошибки;
- блокировать набор при структурных или строковых ошибках;
- покрыть валидные и ошибочные сценарии тестами;
- подтвердить, что текущий генерируемый шаблон читается парсером и сохраняет
  демонстрационные строки.

**Приёмка:** focused-тесты парсера проходят; API и UI не изменены в этой задаче.

## T-02. Заменить ручную форму Excel-сценарием

**Требования:** разделы 4, 5 и 7 SPEC.

**Файлы:** `app/plugins/signal/SIGNAL.py`.

**Работы:**

- удалить ручные поля и обработчики добавления/удаления drafts;
- добавить выбранный файл, «Загрузить из Excel», «Предпросмотр» и «Подробнее»;
- оформить блок по образцу папочной структуры;
- построить таблицу строк, ошибок и статусов;
- при предпросмотре загрузить актуальные атрибуты проекта и отметить
  дубликаты;
- управлять доступностью кнопки создания и инвалидировать устаревший preview.

**Приёмка:** offscreen UI-тест подтверждает отсутствие ручных контролов,
наличие нового workflow и корректные состояния кнопок.

## T-03. Подключить безопасное создание из предпросмотра

**Требования:** разделы 4 и 7 SPEC.

**Файлы:** `app/plugins/signal/SIGNAL.py`, тесты.

**Работы:**

- передавать worker только валидные отсутствующие drafts;
- не запускать worker при ошибках, устаревшем предпросмотре или отсутствии
  новых строк;
- сохранить повторную серверную проверку дубликатов;
- после успеха обновлять обе таблицы и статусы;
- сохранить журнал, подтверждение и существующую обработку сетевых ошибок.

**Приёмка:** автоматические тесты состояния и ручной/offscreen smoke без
реального API подтверждают блокировки и состав drafts.
